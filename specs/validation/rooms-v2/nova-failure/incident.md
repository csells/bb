# Nova's first Workshop request failed

On October 9, 2026, Chris requested separate Atlas and Nova perspectives on a shared task board. Atlas published successfully. Nova's BB-managed Claude turn failed before publishing.

The native BB event reports: `Failed to authenticate: OAuth session expired and could not be refreshed`. Its following failed completion event has no embedded error. Rooms read completion events but omitted provider diagnostics, so it stored a generic error. The UI then excluded terminal failures from its pending cards while retaining the participant's Failed badge. These are distinct authentication, error reporting, and presentation failures.

[Sanitized native evidence](native-failure.json) preserves the exact failed turn and the corrected interpretation without exporting prompts, private tools, capabilities, or credentials. The VM's default login Keychain was also locked: metadata was readable, but reading the credential returned exit36, consistent with `errSecInteractionNotAllowed`. The credential file was absent and the task-owned Keychain item was created at the failed turn's timestamp. This establishes unusable guest credential storage; it does not establish whether token rotation, storage access, or another OAuth condition caused the refresh rejection.

The previously authorized source Claude credential was still valid. It was transferred privately into the disposable VM's mode0600 credential file. The exact failed task-owned guest Keychain item was removed. Source authentication, stable services, provider versions, and the source machine's runtime were unchanged. No credential values were printed or added to this repository. This restores the current staging session; independent long-lived staging authentication and future OAuth refresh remain separate from this repair.

Rooms now reads native provider diagnostics for the matching admitted turn. Recognized failures become fixed public explanations; raw provider details remain private. The mapper rejects other turns, other threads, events outside the accepted turn, and retryable diagnostics, and ignores transient diagnostics when the turn succeeds. Raw failed-completion errors also receive a safe summary rather than being copied into the room.

Failed request cards persist across reload. They show the cause and original request, prepare a follow-up for the failed agent, preserve an existing draft, and give the room owner access to Activity. Preparing a follow-up does not automatically send or replay a request. Both handle fields now use a pattern valid under the browser's Unicode-set regular expression mode.

Verification includes a failing-then-passing admission regression, the actual failed BB events replayed through the mapper, all27 Rooms tests, build/typecheck, and14 browser groups in each of Chromium and WebKit. The browser checks cover failure visibility, reload, owner-only Activity, draft preservation/prefill, and handle validation. Public two-human real-provider verification is recorded alongside this report. The UI asset hashes match the final backend rebuild. All candidate execution remains in the disposable VM.

The exact task-board prompt subsequently passed with real Codex and Claude: each posted independently, both human browsers observed the same messages, and both deliveries finished successfully in15seconds. The QA fixture was removed and its idle native threads archived. Chris's historical failed delivery received a targeted corrected explanation, preserving its failed state and original messages. A fresh browser sign-in to the actual Workshop verified that explanation and the follow-up button: the original draft is prepared with only Nova selected. No message was sent, the draft was cleared, the browser signed out, and the temporary browser credential file was deleted.
