# Two humans, Codex and Claude: public acceptance

The final hosted build passed the twelve mixed-room interaction groups and two separate natural streaming qualifications on October 9, 2026. Atlas used Codex `gpt-6.1-sol`; Nova used Claude Code `claude-opus-5-5`. Every agent activation ran through the disposable VM's BB SDK and provider adapters. The tests used public HTTPS and separately authenticated human browser contexts.

This is **twelve interaction checks plus two focused streaming checks on the same product build**, not one uninterrupted fourteen-check run. Product files stayed unchanged between the successful interaction run and both streaming qualifications. [Final build and tests](budget-fix-build.log) and [client/server hashes](budget-fixed-client-sha256.txt) identify that build.

## Real owner approval and retained failures

The first two mixed runs passed nine conversation groups, then exposed the budget draft race documented in [the controls regression](mixed-provider-controls.md). A focused stale-snapshot test reproduced it; the controlled draft fix passed Chromium and WebKit before mixed attempt3 passed all twelve interaction groups. The initial timing-only explanation was incomplete and is superseded by that diagnosis.

Attempt3's stream observer failed before sending a stream prompt because the TypeScript transpiler injected an unavailable `__name` helper into a browser callback. The callback was revised, then the actual extracted observer executed successfully in a no-model Playwright smoke before further agent calls. Focused streaming avoided repeating the twelve already-passed product checks.

The initial Claude stream waited for a real native command approval. Its exact command invoked only the current activation's Rooms wrapper with `stream begin`. The original observer runner timed out; it did not stop the native activation. A separate short-lived session for the **same QA owner**, issued inside the fixture and revoked afterward, exercised the actual owner Allow once button. [Approval evidence](mixed-public-streams/approval-ui.json) and [decision screenshot](mixed-public-streams/claude-owner-decision.png) record that action. No unrelated command was approved and no duplicate model prompt was sent. That activation completed its public story, but its closed observers could not qualify streaming, so the fresh Claude-only observer run supplies that proof.

The reusable harness now recognizes only the exact current room/agent/activation `stream begin` approval, opens its Details, and clicks Allow once through the original owner's page. Other approvals require manual review. The final Claude-only run's result records whether that guarded approval path was needed.

## Reproduction and scope

Use `apps/rooms/test/participation.browser.ts` inside the disposable candidate VM with a fresh task-owned QA invitation. Set Atlas provider/model to `codex` / `gpt-6.1-sol`, Nova to `claude-code` / `claude-opus-5-5`, and `ROOMS_TEST_STREAMING=1` for the full sequence. `ROOMS_TEST_STREAMING_ONLY=1` isolates streams after fresh human/agent setup; `ROOMS_TEST_STREAM_AGENT=nova` selects only Claude. Never consume the user's Workshop owner claim for acceptance tests.

These results establish the exercised providers, publication protocol and browser behavior. They do not establish every future model's reliability, hostile-tenant OS isolation, or unattended recovery from host reboot. Native restart, steering, interruption and transport-fault evidence are maintained separately. The preview remains staging, not a promoted stable BB installation.

After exporting [the three final QA public transcripts](mixed-public-transcripts.json), cleanup removed 21 explicitly inventoried QA rooms and 21 orphaned QA accounts and archived 13 idle QA BB threads. [Cleanup evidence](mixed-browser-cleanup.json) records the exact IDs. No active or uncertain QA work remained. The transaction verified that Workshop's room, agents, invitations, members and messages were unchanged; Workshop is the only remaining room. Consumed QA invitation files were removed, and the hosted health endpoint remained healthy. Private execution traces remain archived inside the candidate BB for audit.
