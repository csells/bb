Initial Qwen runs could not establish model unreliability while the copied CLI silently skipped execution. Failed runs remain preserved alongside their corrected diagnosis. Controlled chunk publication proves the stream protocol; the later genuine Codex and Claude runs provide separate natural-stream evidence. See [native-provider research](../../research/rooms/09-native-providers-and-steering.md) and [runtime evidence](../../research/spikes/explicit-participation/runtime-v2/README.md).

These verify exact submission proof, preserved queued follow-ups and fencing without replay; the original input's completion does not release an unresolved steering lease. ## Hosting and isolation

Execution, builds, data and agent workspaces remain in the disposable Rooms VM. BB owns agent projects, environments, persistent top-level threads, provider sessions, tool execution, steering and cancellation; Rooms calls BB's SDK and provides room identity, delivery and explicit publication. The untouched Workshop is configured with Atlas on Codex and Nova on Claude. The temporary Safari VM was deleted after exporting evidence. Stable BB and Buzz were not modified. The supervised host HTTP relays expose the VM and the owner-only initial claim; the claim uses fresh replacement data and its token remains unconsumed. Current endpoints, lifecycle and authentication state are maintained in the home-lab registry record `bb-rooms-stage`. The [hosting checkpoint](hosting.md) explains supervision and the temporary tunnel's restart limitations.

The user authorized replacing this disposable preview. No stable BB merge or promotion has occurred. The preview uses separate agent directories under one OS account and is intended for trusted collaborators, not hostile tenants.
