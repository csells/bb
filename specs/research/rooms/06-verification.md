# Verify boundaries before declaring rooms ready

Research establishes why explicit participation is necessary; it does not prove our new implementation works. The existing hosted preview's successful two-human/two-model tests are historical evidence of connectivity, membership and execution. They do not establish authenticated agent publication, successful silence, durable peer delivery or selected public streaming. Replacement acceptance must target those missing semantics rather than count reply bubbles.

## Executed reference fixtures validate specific mechanisms

Gas City reference tests completed in `/Users/admin/gascity-participation-spike` inside the disposable Rooms VM. **46 top-level Go tests passed with `-race` (55 passing events including subtests), and 88 Python tests passed.** They exercise pinned upstream code with fake Slack/GC endpoints, including routing, receipts, immutable turn references, fanout and recovery. They do not prove live Slack credentials, live model compliance, or our BB integration. [Commands, machine-readable result and logs](../spikes/gascity-reference/README.md).

Buzz and Work Together conclusions come from pinned source inspection. Their tests were read, not rerun against those services. No stable BB or Buzz runtime was changed by this research. Source limitations are retained in the chapters: Buzz's personal browser identity, owner-only activity streaming, bounded replay; Gas City's one-hop formal delegation and ordinary-reply durability gap; unavailable Work Together companion behavior.

## The controlled protocol spike completed

A scratch broker and CLI were exercised under `specs/research/spikes/explicit-participation`, in `/Users/admin/rooms-participation-spike` in the disposable VM. The source implements immutable actor/room/activation capabilities, explicit post/request, public stream lifecycle, acknowledgment and settlement with SQLite persistence. **12 deterministic protocol assertions passed**, including conflicting stream-commit recipient retries returning 409, immutable two-room capabilities and cancellation fencing surviving broker restart. A controlled real two-agent BB/Pi fixture passed **11 assertions**: separate A/B CLI posts, private simulated dialogue and raw mentions remaining unpublished, explicit begin/append/commit producing one message, chunks causing no wake, and no-post completion returning idle. These results exercise exact commanded tool sequences, not autonomous social-policy selection. The first two live attempts failed through a model refusal and malformed JSON/command ordering. The busy-tool test also passed: a second human message was durably accepted while AgentA ran a real sleep tool, BB returned a queued receipt, and AgentA later observed it. This proves native busy queueing, not active-turn steering. The scratch broker still records that delivery queued because the fixture does not implement automatic queue-to-provider reconciliation. The latest detailed checkpoint is [the spike handoff](../spikes/explicit-participation/HANDOFF.md).

The essential negative test is that an agent can emit a fake multi-speaker transcript privately and create zero public messages. Positive tests must prove each real agent posts under its own credential, one targeted post wakes only its intended peer, no-post completion reaches idle, and a useful conversation can exceed two exchanges. Two humans must submit while agents are active without identity loss or dropped input. Streams must reconnect into the same public message without waking peers per chunk. Lost acknowledgments, restart, cancellation and revocation must not allow duplicate posts or stale publishers.

## Remaining uncertainty must be explicit

Model-authored public streaming through actual provider tool calls has not been established. Generic begin/append tests cannot close that gap. The implemented CLI binds each activation to an immutable capability, and real SQLite tests cover leases, membership, notification intent and stale-publication rejection; the scratch broker alone does not prove those candidate behaviors. An independent review found a conflicting commit retry that changed recipients; it was fixed to return 409 and added to the deterministic fixture. Natural dialogue now passes after correcting the compiled CLI defect; natural streaming remains a separate gap. Same-UID processes sharing a filesystem are not strong credential isolation; the preview is explicitly for trusted collaborators. Actual Claude/Codex authentication and adapter behavior must be validated separately from the currently available Pi/model path.

The user authorized replacement of the preview and requested necessary spikes. Candidate implementation therefore proceeds without another conceptual approval gate. Promotion into the stable BB installation remains a separate action under the global isolation rules. [Current handoff](CURRENT-HANDOFF.md) records working directories and pending artifacts; [replacement plan](../../plans/0002-rooms-replacement.md) orders the remaining work.

## Replacement candidate integration — October 9

The replacement now has real SQLite protocol tests, typed native admission proof, an agent CLI, SDK/human CLI parity, explicit publication, ordered public chunks, independent durable deliveries and visible controls. The final compiled build and typecheck pass in the disposable VM; 24 Rooms tests and 857 CLI tests passed, with one CLI test skipped. Browser acceptance against the public HTTPS gateway passed two separately authenticated humans, concurrent messages, retry identity, persistence, anonymous/forged-author rejection and live membership revocation. The final combined public-browser suite passed **12 groups** on the final prompt/build using real Pi agents with `qwen3:4b-instruct-2507-q4_K_M`: two humans, distinct real agent authors, an actual peer request, notice silence, busy follow-up queueing and Stop, policies, owner Activity with member HTTP 403, reload and mobile interaction. Chromium and Playwright WebKit passed the final minified client's synthetic pending/streaming/drawer checks, including visible status failures and recovery.

Actual iPhone 17 Pro / iOS 27 Simulator Safari found two real defects: 14px inputs caused focus zoom, and the custom drawer height omitted the keyboard inset. Both were corrected; the same keyboard/closing/composer test passed. The [Safari report](../../validation/rooms-v2/ios-safari/README.md) records its exact source-CSS fixture and the later final-minified WebKit check separately. None of these browser checks establishes agent autonomy.

The first production-harness attempts caught missing migration files in the compiled server bundle and a native BB events pagination limit (100, not 500). Both were fixed. Initial Qwen runs produced no public contributions, but a deeper recursive trace found actual Bash calls nested inside turn records. The copied CLI silently skipped its entrypoint because Node resolves macOS `/var` aliases differently from the command argument. A dedicated executable entry module fixed that defect; **four compiled-CLI subprocess checks passed**, including the copied macOS path and authenticated publication. Earlier attribution to model tool-choice failure was premature. Actual HTTP metadata confirms Bash advertisement. Failed evidence and corrected analysis are retained in [runtime acceptance](../spikes/explicit-participation/runtime-v2/README.md).

The integrated candidate then passed **14 controlled native lifecycle checks**: two actual agents invoked supplied CLI fixtures; private simulated dialogue stayed private; explicit scripted chunks updated one public stream; gateway restart reattached without replay; a second human's native steering persisted and the agent published its observed effect; Stop rejected a delayed publisher and prevented final publication. These supplied commands and chunks establish actual runtime integration, not autonomous composition. **Five separate native status-recovery checks passed** using a real previously admitted activation, including clearing a transient error without redispatch.

Natural run 7 passed **six checks** covering independent human and actual agent identities, top-level BB threads, more than two peer handoffs followed by idle, and a second human's notice completing without a public reply. It then failed the natural-streaming assertion: the model supplied unsupported arguments to `stream begin`, and its private fallback story remained unpublished. This run predates the final asynchronous-request/shared-goal wording; the final 12-group public-browser suite validates natural participation on that final prompt/build.

The final fresh-agent streaming attempt used the available thinking `qwen3:4b` model. It completed with a private reasoning operation, **zero actual tool calls and zero public messages**, so the unchanged model-authored streaming assertion failed. Scripted stream tests and the passing browser suite do not close this gap. **Natural streaming remains unqualified**, and permission to copy credentials for stronger-provider verification remains pending. See the [candidate verification report](../../validation/rooms-v2/README.md).

[BB admission research](07-bb-admission-and-recovery.md) now supplies a stronger completion boundary: correlate the activation's request with accepted and terminal provider events. A successful native queue deletion has separate persisted cancellation proof. Missing admission acknowledgments remain uncertain. These failure findings changed the implementation; they were not waived to make a demo pass.
