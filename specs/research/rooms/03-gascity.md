# Gas City distinguishes visibility from activation

The useful reference is **slack-full's company-room path**, not every Slack pack. It binds named agents to independent sessions and requires an explicit CLI action for public speech. The simpler packs demonstrate why feature names are insufficient: slack-mini targets one mayor, while slack-channel fans human messages into sessions but rejects bot messages and uses cosmetic identity overrides on one bot. Neither alone supplies the desired peer conversation. ([mini filter](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-mini/adapter/main.go#L405-L460), [channel routing](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-channel/adapter/inbound.go#L54-L128), [channel identity overrides](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-channel/adapter/outbound.go#L51-L96))

## A public post is deliberate and authenticated

The full company-room prompt explicitly keeps plain assistant output private. An agent speaks with `gc slack reply-current --turn-ref ... --body-file ...` and checks the JSON posting receipt. It must not prefix its own name because the bot identity supplies attribution. Directory identity persists independently of a transient runtime session; one room/agent binding identifies the execution destination. ([Prompt contract](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/template-fragments/slack-v0.template.md#L49-L72), [bindings](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/docs/company-rooms.md#L104-L160))

The immutable `turn_ref` binds receipt, session, city, agent and wake kind before submission. It prevents a later Room2 message from changing where an earlier Room1 activation replies. This is directly relevant to BB's missing trusted turn context: a mutable current-room pointer is not adequate routing authority. ([Turn records](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/adapter/company_turn.go#L22-L146), [cross-room regression](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/tests/test_slack_chat_reply_current.py#L929-L1005))

## Reading a message does not require answering

Wake types include ambient context, targeted requests, peer delegation, peer result and optional peer input. Their instructions arrive with authenticated routing metadata on each turn. Explicit human mentions select only the addressed eligible members. Trusted agent posts wake only explicitly mentioned peers; self, unknown bots and unmentioned bot posts do not create work. Earlier authenticated thread participation enrolls an agent for later untagged **human** follow-ups, not every agent echo. ([Per-turn response contract](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/adapter/company_hydration.go#L440-L494), [routing](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/adapter/company_routing.go#L267-L364), [thread participation](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/adapter/company_thread_ambient.go#L28-L89))

This pack also imposes a real limitation we should **not copy silently**. Formal delegation accepts human-rooted turns but rejects peer-derived turns, imposing a one-hop workflow. Ordinary replies strip live mentions and synthesis does not wake teammates. That intentionally settles a managed work workflow; it is not an unrestricted debate algorithm. BB should reuse typed notification and no-post semantics while designing its requested open discussion behavior explicitly. ([One-hop enforcement](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/scripts/slack_company_outbound.py#L1912-L1972), [ordinary reply behavior](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/scripts/slack_company_outbound.py#L2368-L2399))

## Delivery receipts are stronger than transport acceptance

Ingress is persisted before Slack acknowledgment, keyed by canonical origin, with first-writer creation and generation-checked updates. Fanout submits every target before waiting, preventing one slow model from blocking its peers. Async request IDs and event cursors distinguish HTTP acceptance from delivered input. Formal delegation/result paths use durable outbound intents, but ordinary root replies directly post and lack that protection; the broad design prose should not obscure this implementation gap. ([Ingress](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/adapter/ingress_receipts.go#L22-L83), [fanout](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/adapter/company_delivery.go#L1006-L1098), [event correlation](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/adapter/company_async_delivery.go#L179-L249), [unprotected root reply](https://github.com/gastownhall/gascity-packs/blob/520e95cb22992a8a1017f7a60da267f203497c7e/slack-full/scripts/slack_company_outbound.py#L2368-L2399))
